## Global Constraints

### Decisions (locked in brainstorming 2026-09-06)

- **D1 — Slice order and scope.** Student remainder (this slice) → Authoring → Teacher → one final polish slice. 9d is applied to the **five student surfaces only** (`CourseList`, `CourseView`, `SequencePlayer`, `QuizItem`'s empty branch, `MiniProjectDetailPage`); teacher/authoring tabs adopt the primitives in their own slices. Polish/taste findings go to `docs/backlog/`, one file each.
- **D2 — Three small primitives, not one.** `Skeleton`, `EmptyState`, `ErrorState`, each with one job, its own test file, and **no prop that no Slice-4 consumer uses** (rev 2: `EmptyState` is `title`-only; `ErrorState`'s `onretry` is inline-only and `action` page-only — §1). **One recorded exception:** `Skeleton.label` — every consumer takes the default `Loading…`; the prop exists because the sr-only text must have *a* value and a prop with a default is the smallest way to make that value testable and overridable without a second component. `Spinner.svelte` is untouched and keeps its **page/section-level** users (`App.svelte:69`, `Login.svelte:90`, `VersionsPage.svelte:152`, `VersionEditPage.svelte:285/291`, `ItemEditPage.svelte:261`; in-flight buttons use `Button`'s own `.spinner`, `Button.svelte:29`, not this component). `LoadingPlaceholder` stays for its teacher-page users. Neither is deleted.
- **D3 — The "Late" pill is grey, not amber.** `ref 1320` paints it `--status-needs-revision-*`; `mathion-visual-spec.md:132-133` says *"`needs revision` is the only amber in the product and must not be confused with the gold chrome"*. The spec rule wins: "late" is a fact about the past, not a call to act. Late uses `--status-not-submitted-bg/fg`. **The one recorded pixel deviation from the artboard.**
- **D4 — Every date on the page keeps the shared helper's format** (`formatLocalWithTz`, `lib/datetime.ts:20-26`: `2026-08-21 23:59 GMT+2`, pinned to `shortOffset` for cross-browser stability): the deadline line and aside (`ref 1273-1274`), the history header (`ref 1301` `02 Aug 2026`) and the evaluator date (`ref 1311`). No second formatter. Wording deviation only, at four sites.
- **D5 — Drop zone: click to pick AND drag-and-drop.** A `<label>` styled as the dashed box over a visually-hidden native `<input type="file">`; `dragover`/`dragleave`/`drop` handlers feed the **same `acceptFile(f)`** body as the picker's `onchange`, so the `.pdf` / 20 MB guards (which run in `handleSubmit`, `:277-288`, not at pick time) and the `success → idle` transition apply identically. **Recorded semantics:** `selectedFile` is the single source of truth for what gets submitted (`handleSubmit` reads it, `:272-276`); a dropped file is **never** written into `fileInputEl.files` (browsers do not allow it without a `DataTransfer` round-trip, and nothing reads `input.files` after the pick). **An accepted drop clears the native input (`fileInputEl.value = ''`) after the submitting guard** — otherwise the sequence *pick A → drop B → re-pick A* leaves `input.files = A` while `selectedFile = B`, and re-picking the identical file fires no `change` event (the same browser rule the success path already works around, `:378-382`), so Submit would silently send B. With the clear, the re-pick fires and `selectedFile` becomes A. That sequence is a T4 test. Copy is the artboard's: `Drop a PDF or click to pick`.
- **D6 — Uniform full card for every history entry.** The artboard collapses older rejected submissions to one mono line (`ref 1322/1330`); Mathion renders every entry the same way (header strip + file tile + feedback block when evaluated), because a rejected evaluation can carry a feedback file that must stay reachable, and one template is one test. Deviation from the artboard in *density* only; every element of the full card is on the artboard.
- **D7 — The 9d states render inside their own card.** The artboard wraps each state in a bordered `--surface` card whose label strip is annotation (`ref 1345` "loading — skeleton rows, never a spinner"). The card border is taken as product chrome (it is what gives a skeleton its row height and an empty state its extent inside a page that otherwise has no container); the label strips are not built.
- **D8 — Evaluation-result pills reuse `StatusPill`.** `StudentSubmissionHistoryEvaluation.result` (`types.ts:490`) is a 4-value subset of `LatestStatus` (`types.ts:454-461`), so `<StatusPill status={ev.result} />` is type-correct as-is and yields the same label/class/glyph the page header uses. No new pill component, no second copy of the status table.
- **D9 (rev 2) — Page-level error states keep an `<h1>`.** `ErrorState`'s page variant renders its title as `<h1>` (styled to the artboard's 14px), so `CourseView:34/37/40`, `SequencePlayer:166/169/174` and `MiniProjectDetailPage:410`, which all render `<h1>` today, keep their heading landmark. `role="alert"` is an announcement, not a heading; both are kept.

## Per-surface design

### 1. The 9d primitives — T1

All three are `components/ui/*`, presentational, no store access, no `navigate`. Geometry pins cite artboard 9d; every colour is a token.

**1.1 `Skeleton.svelte`** — props `rows: number = 3`, `label: string = 'Loading…'`.
```svelte
<script lang="ts">
  // The three artboard rows, ref 1347/1348/1349, cycling for rows > 3.
  const W: ReadonlyArray<readonly [number, number, number]> = [[180, 90, 64], [220, 70, 64], [150, 110, 64]];
  let { rows = 3, label = 'Loading…' }: { rows?: number; label?: string } = $props();
</script>
<div class="skeleton" role="status" aria-live="polite">
  <span class="sr-only">{label}</span>
  {#each { length: rows } as _, i}
    <div class="row" aria-hidden="true">
      <span class="bar" style:width="{W[i % 3][0]}px"></span>
      <span class="bar" style:width="{W[i % 3][1]}px"></span>
      <span class="bar end" style:width="{W[i % 3][2]}px"></span>
    </div>
  {/each}
</div>
```
Card: `border: 1px solid var(--border); border-radius: var(--radius); background: var(--surface); padding: 12px /* ref 1346 */; display:flex; flex-direction:column; gap: 9px /* ref 1346 */`. ## Testing strategy

`mount`/`unmount`/`flushSync` only (never `@testing-library`); TDD RED→GREEN per task; assert **load-bearing structure/classes/text/aria**. jsdom cannot compute the cascade → geometry/colour pins are verified by `svelte-check` (no `css_unused_selector` growth), `vite build`, and the **hash-coupled dist-CSS greps** of the Slice-3 gate (declaration-level regexes terminated at both ends, anchored on a gate-verified-unique class hash, parentage checked for the forced-colors block). **Anchor collisions to hash-qualify (Slice-3 collision-count convention):** exact-name collisions `.empty-state` ×3 elsewhere (`RunSubmissionTab.svelte:383`, `RunAssetsTab.svelte:931/953`) and `.pills` ×1 (`TeacherRunListPage.svelte:144`); **prefix collisions** that a `\.drop\b`-style regex would still match: `.drop` vs `.drop-zone` (`AssetSidebar.svelte:344-346`) and `.precondition` vs `.precondition-banner` (`MiniProjectModal.svelte:553`) — every anchor regex is therefore written as `\.NAME\.svelte-<hash>` (the hash immediately after the name), never `\.NAME\b`; the remaining anchors (`skeleton`, `error-state`, `history-entry-header`, `feedback`, `entry-meta`, `group-notice`, `file-kind`, `submit-error`) have no existing rule and are re-verified at gate time. Per task, the plan supplies: the test code, the source greps, the dist greps with their anchors, and the mutation checks ("delete the line, watch the named test fail, restore") for every guard the gate would otherwise miss — the Slice-3 lesson.

**Per-task gate** (inherited): svelte-autofixer clean on each edited `.svelte` → `npm test` (full suite) → `npm run check` (0 errors, warnings ≤ 31) → `npm run build` → the task's greps. Then codex@high + first-party@Opus-xhigh review, fix, re-review until clean, user OK.

**Correctness-axis lane.** One review round per task is pointed explicitly at *rendered* correctness (not gate-detectability): narrow widths (320px: the grid collapses, the filename and title wrap, the deadline aside drops under), a 24-character status label in the header strip, a group with eight members, an assignment with a list.

**Browser pass (user-owned, end of slice)** against the real stack: `./run-slice3-surfaces.sh` (backend :8000, six mini-project states with real submission and feedback files; `--ungrouped` for the pending-group card), `npm run dev` in `frontend/` (:5173), the reference canvas open beside it. Checklist: the six 9c states (not submitted / awaiting / rejected / major / minor / accepted) + pending group; a submit with a dropped PDF and with a picked PDF; **drop a non-PDF, then press Submit** (the guards run in `handleSubmit`, not at pick time — the inline error appears on Submit); the fetch-error page (`/courses/demo-course/blocks/no-such-block/mini-project` → 404 state); `/courses` skeleton (throttle the network in devtools) and its inline error with Retry (stop the backend, Retry, start it); the empty course list needs a user with no enrolments — verify the `EmptyState` visually on `/courses` by temporarily withdrawing the demo enrolment via the seed's `--remove` or accept the primitive's own test as sufficient (user's call at pass time).
