## Global Constraints

Inherited verbatim from Slice-1/2 (every task implicitly includes these):

1. **Colours → tokens.** No hardcoded hex outside comments/brand-art. Every colour resolves to a token in `frontend/src/styles/theme-default.css`. **No new colour tokens** — the option control uses `--border-strong`/`--primary`/`--primary-soft`/status tokens only (§3).
2. **No opacity-based disabled/dim.** Recede via tokens (`--faint`, `--muted`, `--border-faint`, `--surface-2`), never `opacity`. (Note: the sr-only native inputs in §3 use `opacity:0` for *visual hiding of a still-focusable control*, not a disabled treatment — the Slice-2 segmented annotation, `Login.svelte:137`; repeat that annotation so it does not read as a violation.)
3. **No *decorative* glyphs on Slice-3 surfaces** (visual-spec §5.8 "No emoji anywhere", `mathion-visual-spec.md:326`). Slice-3 replaces five decorative glyphs with SVG marks: `✓` in `VideoItem` (`VideoItem.svelte:37`), `✓` in `SequenceLink` (`SequenceLink.svelte:19`), `📋` in `MiniProjectLink` (`MiniProjectLink.svelte:44`), and `▾`/`▸` in `BlockGroup` (`BlockGroup.svelte:24`). **Carve-out (do NOT remove):** the `LATEST_STATUS_META` glyph tokens `✓ · ~ × ! …` (`studentMiniProjects.ts:44-50`) are the deliberate **non-colour, colourblind status signal** (C14) rendered by `StatusPill`; they stay, and `StatusPill.svelte.test.ts:31` continues to assert them. (Tension noted: `ui/StatusBadge.svelte:18-19` cites the same rule to justify having *no* glyph; only `✓` here is pictographic, retained under C14 — an intentional divergence.) Emoji on deferred surfaces are out of scope. **Every new decorative SVG** (the VideoItem check, the checkbox check, the three reveal marks, the BlockGroup chevron, the ItemMark type marks) follows the repo convention (`ItemIcon.svelte:22`, ref `:2113`): `aria-hidden="true"`, `viewBox="0 0 16 16"`, `stroke="currentColor"` (or `fill="currentColor"` for solid marks), `stroke-width` ≈1.6–1.9, round caps/joins, sized ~11–14px, colour inherited from the parent's status/text token — so a reveal mark's meaning reaches AT via the sibling `.sr-only` text, not the SVG. Exact `points`/`path` geometry is plan-level (copy the reference's, e.g. the check at ref `:1039` `polyline points="3,8.6 6.4,12 13,4.6"` — `:1038` is the enclosing strip `<div>`); the focused tests assert `svg[aria-hidden="true"]` on each.
4. **Mono for every numeral** (`--font-mono`) — item counters, "Question N of M", attempts count, progress ratios, the `S{n}` prefix, the numeric-answer field value. Reference mock-ups that spell a number ("Two attempts left", ref 2134) do not override this — the app renders a digit, so it is mono.
5. **Per-component literals — three permitted forms** (verbatim from the Slice-2 plan, `:23`): (a) a geometry literal **matching a reference line, annotated `/* ref NNNN */`**; (b) where the branch has **no reference counterpart**, a literal with a comment stating that and naming the scale it matches; (c) for **implementation mechanics** (sr-only sizing, focus-ring width), a literal with a comment explaining the mechanism. **Literals are geometry ONLY** — never colours (Constraint 1). (Slice-3 uses all three: `/* ref 2127 */` metrics; the no-ref SequenceLink/MiniProjectLink/BlockGroup/StatusPill row metrics; the sr-only 1px box + 2px focus ring copied from `Login.svelte:137-146`.)
6. **Dense control metrics are final** (visual-spec §4): `--control-h` 30px, `--control-pad-x` 9px, field value 13px, `--btn-pad` 4px 10px, `--btn-pad-sm` 4px 9px, code/textarea blocks 8px/10px.
7. **`ItemIcon`/`ItemMark` states** (Slice-1) — the existing prop union is **`'covered' | 'current' | 'not-yet'`** (`ItemIcon.svelte:4`); "not started" is prose only, never a literal value: covered = `--primary` fill/white mark; current = `--primary-soft` + 1.5px `--primary` border + `--primary` mark; not-yet = `--surface` + 1px `--border-strong` + `--muted` mark.
8. **No backend/API/route/schema change.** The quiz submits the whole answer-map in one POST (`QuizItem.svelte:84`); coverage trackers (page 30s `:11-30`, video mark-watched `:13-28`, interactive on-load `:33-70`) and all routes are untouched. Every behaviour touch is client-side and enumerated.

### Decisions (locked in brainstorming; D4 corrected in round 2)

- **D1 — Quiz stays all-at-once (restyle only).** Questions stacked with one Submit; no state/backend change.
- **D2 — Quiz reveal: status-colour + a non-colour mark + screen-reader text, an explicit extension of visual-spec §3** (which assigns green/red to *submission* states, not quiz correctness — `mathion-visual-spec.md:110-122`). *Choice* questions (correct_option_ids present) get a **four-state** reveal (§3): the **three evaluative states** — chosen-correct, wrong-pick, missed-correct — each carry a distinct class, a status colour, a non-colour SVG mark, **and** a visually-hidden status label for assistive tech (the native inputs are `disabled` after reveal, so the colour/mark alone is not exposed to AT); the **neutral** state gets a bare `reveal-neutral` class with no colour, mark, or label. *Numeric/Text* questions have **no per-question `is_correct`** (`QuestionReveal`, `types.ts:161-170`), so they show **only the correct answer** and **deliberately do not judge** the student's value.
- **D3 — CourseView adopts an accordion + chain** via a new presentational `ItemMark` primitive (D5). Blocks = §4 accordion sections; each sequence row shows a **non-interactive** `ItemMark` chain + mono progress. The accordion becomes **keyboard-operable** (native `<button>`; enumerated C1).
- **D4 — Footer primary: a three-way predicate.** `flatItems` is **course-wide** and `next()` advances across sequence and block boundaries (`SequencePlayer.svelte:99-100,123-125`); `flatIndex` is `-1` while the item is unresolved (`:112-114`, first render pass before the hash `$effect` `:76-85` runs). The primary Button is:
  - `flatIndex < 0` (unresolved) → **disabled**, label `Next →` (matches today's `disabled` at `:184`);
  - `0 <= flatIndex < flatItems.length - 1` → **enabled** `Next: {next item title} →` (title from the extended `FlatRef`; `Next →` when the title is empty/whitespace), crossing sequence/block boundaries **exactly as today**;
  - `flatIndex === flatItems.length - 1` (course-flat end, today a disabled no-op) → **enabled** `Finish sequence` → `navigate('/courses/{courseSlug}')`.
  Previous = secondary, `disabled={flatIndex <= 0}`, still crossing backward. Disabled buttons carry a **state-appropriate** `title` reason (visual-spec:159): Previous → `title={flatIndex < 0 ? 'Loading…' : flatIndex === 0 ? "You're on the first item" : undefined}` (Previous is disabled for BOTH `-1` and `0`, so a fixed "first item" string is false while unresolved); disabled primary → `title="Loading…"`. **All forward cross-sequence navigation is preserved** — the only change is turning the currently-disabled *terminal* button into an enabled "finish". This adapts ref 10h's `Finish sequence` label (`:1049`, shown there on a sequence's terminal item) to this app's **course-wide** flat model: it appears only at the course-flat end and navigates to `/courses/{slug}`, while sequence-internal boundaries keep `Next: {title} →` (ref 2c). The label is retained despite the sequence-vs-course-flat difference (a deliberate, documented deviation).
- **D5 — New additive primitive `ItemMark.svelte`.** Presentational 22px square + type SVG mark + state, a non-interactive `<span aria-hidden="true">` with **no text node**. Props: `type: Item['type']` (inline indexed type — **no `ItemMarkType` alias**, to keep the public API deterministic), `state: ItemMarkState` with a **`state = 'not-yet'` default** (so consumers with no state — the MiniProjectLink flag — need not supply one); T6 adds exactly `export type ItemMarkState = 'covered' | 'current' | 'not-yet'` to `types.ts`, and `ItemIcon.svelte`'s local `type State` (`:4`) is replaced by importing that shared alias. `ItemIcon.svelte` is **refactored to `<button class="icon {istate}" …><ItemMark type={item.type} state={istate}/></button>`** — the state class **stays on the button** (`ItemIcon.svelte.test.ts:33-36`), the button forwards `state`, gets **`display:inline-flex`** (the rest of a button reset — `padding:0;border:0;background:none;cursor:pointer` — is already global, `reset.css:8`), and keeps `ItemMark`'s SVG reachable as `button svg` (`ItemIcon.svelte.test.ts:28,:39-48`) with empty `textContent` (`:30`). `ItemMark` takes only `type`/`state` (no `class`/other props); consumers that need a class wrap it in a styled span. `SequenceLink` (chain) and `MiniProjectLink` (single flag) use `ItemMark` directly.
- **D6 — `StatusPill` authored from scratch, component-scoped, always rendering `.pill-token`.** It has **no `<style>` block** today; the `pill-*` classes resolve to nothing. T8b writes the pill geometry + class→token table (§4) as **Svelte-component-scoped** CSS, and the component **always renders a `.pill-token` child** (from `LATEST_STATUS_META`). Consequences: (a) the scoped styles travel with `<StatusPill>` to every consumer, including the deferred `MiniProjectDetailPage:425` usage; (b) the **raw** `<span class="pill pill-warning">Late</span>` at `MiniProjectDetailPage:527` and the **separate** teacher-side pill family (`RunMiniProjectsTab:242` with its own scoped `.pill`/`.pill-published`/`.pill-locked` at `:397-408`) are **not reached** by StatusPill's scoped CSS and are each their own surface's responsibility (Slice-4+); (c) scoping (not a global `.pill`) preserves visual-spec §3's one-amber rule.

## Enumerated changes (the non-pure-CSS touches)

All client-side; none touch the backend/routes/schema.

**(A) Behaviour / state:**
1. **`FlatRef` gains `title: string`** (`SequencePlayer.svelte:101-110`) for the footer label. Ordering logic unchanged.
2. **Footer "Finish sequence"** (D4): at the course-flat end only, the primary calls `finish()` → `navigate('/courses/{courseSlug}')`. Existing route (`routes.ts:7`); forward cross-sequence `Next` preserved.
3. **Attempts remaining stays accurate across "Try again"** (`QuizItem`): `attemptsUsed` (`:29-34`) falls back to the course-store count, which `submit()` never bumps and `tryAgain()` (`:96-101`) resets `lastResult` — so after submit→Try again it would read the *stale* store count. Add `let lastAttemptCount = $state<number | null>(null)`; set it from `res.attempt_count` on submit success; insert it into the `attemptsUsed` fallback chain **before** the store lookup; **`tryAgain()` does not reset it**. (The `lastResult?`/`revealed?` links in the chain are unreachable at the `!locked` render site — kept for correctness/other future readers.) Client-only.
4. **Choice reveal derivations** (§3): client-side `isChosen` (`selected === opt.id` for single; **`selected.has(opt.id)`** for multi — `value` is `number[] | string | undefined`, so `.includes` on it would not type-check) + `isMissedCorrect = isCorrect && !isChosen && studentAnswered`, where `studentAnswered` = the student made ≥1 pick for this question (guards the auto-reveal-with-null-`student_answer` case, `valueFor` `:39-45`, so an unanswered question's correct options render `reveal-neutral`, not dashed missed-correct).
5. **`SequenceLink` drops the `formatProgress` import** and renders a mono `{covered}/{total}` (no spaces, matching CourseCard) — `formatProgress` returns `"{covered} / {total}"` *with* spaces (`format.ts:2`); `format.test.ts` keeps the helper covered (it is retained deliberately as a shared, test-covered helper even though this removes its last production consumer); `SequenceLink`'s non-reactive `total`/`href` become `$derived` (removing its three `state_referenced_locally` warnings at `8:17`,`12:28`,`12:46`). (Ratio conventions are intentionally context-specific: the SequenceLink **progress** ratio is `{covered}/{total}` no-spaces, matching CourseCard; the quiz **score** stays `{correct} / {total}` with spaces, `QuizItem.svelte:164` — a score, not a progress count.)

**(B) Copy / rendered strings:**
6. **Quiz Submit label:** `Submit` → **`Submit answer`** (`QuizItem.svelte:157`; ref 2133).
7. **Breadcrumb copy redistribution** (`SequencePlayer.svelte:151-156,166`): drop the `←` prefix on the course crumb; reformat `B{order}. {title}` → **`B{order} · {block title}`** (the `{n}` is `currentBlock.order`, not a positional index); move `S{order}` out of the `<h1>` into the crumb.
8. **Footer Next label:** `Next →` → **`Next: {title} →`** (item 1 supplies the title).
9. **VideoItem watched confirmation:** `✓ Marked as watched` → inline check SVG + text, both `--status-accepted-fg` (`VideoItem.svelte:37`).
10. **Per-question label:** a mono `Question {i} of {n}` label added before each question (§3 T4).
11. **Attempts line copy:** `Maximum N attempts per quiz (X used)` → **`{remaining} {attempt|attempts} left`** (`QuizItem.svelte:174`), `remaining = Math.max(0, max - attemptsUsed)`, singular "1 attempt left", mono numeral, 12.5px `--muted` (ref 2134); **suppressed when the course snapshot is absent** (`currentCourse.value === null` — the only reachable state where `max_quiz_attempts` is unavailable, it being a required `number` in `VersionContent`, `types.ts:30-35`; this guard is unreachable *in-app* — `ItemRouter` renders behind `{#if currentItem && currentCourse.value}`, `SequencePlayer.svelte:177` — but is kept because `QuizItem` is independently mountable in tests, unlike the same-component `currentBlock` derivation Round 3 dropped); renders in the **pre-submit (`!locked`) state only** (a conditional-render touch — structural, cross-listed here with the copy change).

**(C) Structural / accessibility:**
12. **BlockGroup accordion becomes keyboard-operable** (D3): pointer-only `<header onclick>` → native `<button aria-expanded aria-controls>` + `role="region"` panel (T8a; drops the 2 baseline a11y warnings).
13. **`ItemIcon` refactored to compose `ItemMark`** (D5) — presentational split, no behaviour change.
14. **Five decorative glyphs → SVG** (Constraint 3) — VideoItem/SequenceLink `✓`, MiniProjectLink `📋`, BlockGroup `▾/▸`.
15. **Per-option reveal SR text + disabled-button `title` reasons** (D2, D4) — new assistive-tech-only strings.

Everything not in (A)-(C) or implied by the per-surface styling is pure CSS/token work.
