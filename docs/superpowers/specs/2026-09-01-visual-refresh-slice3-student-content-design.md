## Global Constraints

Inherited verbatim from Slice-1/2 (every task implicitly includes these):

1. **Colours → tokens.** No hardcoded hex outside comments/brand-art. Every colour resolves to a token in `frontend/src/styles/theme-default.css`. **No new colour tokens** — the option control resolves to **existing** tokens only (`--surface`, `--surface-2`, `--text-2`, `--muted`, `--border-strong`, `--border-faint`, `--primary`, `--primary-soft`, `--primary-text`, `--status-*`; all in `theme-default.css`) — the rule is "no *new* tokens", not a closed subset (§3).
2. **No opacity-based disabled/dim.** Recede via tokens (`--faint`, `--muted`, `--border-faint`, `--surface-2`), never `opacity`. (Note: the sr-only native inputs in §3 use `opacity:0` for *visual hiding of a still-focusable control*, not a disabled treatment — the Slice-2 segmented annotation, `Login.svelte:137`; repeat that annotation so it does not read as a violation.) **Documented deviation for disabled *text* (§3 T2 locked option row, T3 numeric/text field):** the authority's disabled recipe is `--faint` text + `--border-faint` border + `--bg` background (`mathion-visual-spec.md:159`, implemented at `Button.svelte:46-51`), but Slice-3 uses **`--muted` text + `--surface-2` bg + `--border-faint` border** — because `--faint` (#B4B9C4) fails AA as *read* text and this same spec reserves it for glyphs/carets/separators (`:62-66`); the disabled option/field text must stay legible. A deliberate, contrast-driven asymmetry with `Button`'s disabled **action labels** (Previous / Next / Submit — `Button` renders arbitrary child text, `Button.svelte:29`, not a glyph): those name an **unavailable action** and may recede toward `--faint` per visual-spec:159, whereas the option/field text is **answer / input content the student must still read**, so it stays `--muted` (`Button` renders arbitrary child text at `Button.svelte:30`, `{@render children?.()}` — `:29` is the spinner) — recorded so a reviewer doesn't "correct" `--muted` back to `--faint` (codex-r13-M2 / revA-r14-M1).
3. **No *decorative* glyphs on Slice-3 surfaces** (visual-spec §5.8 "No emoji anywhere", `mathion-visual-spec.md:326`). Slice-3 removes five decorative glyph occurrences across four sites — **four become SVG marks, one is removed outright**: `✓` in `VideoItem` → check SVG (`VideoItem.svelte:37`), `📋` in `MiniProjectLink` → `ItemMark` SVG (`MiniProjectLink.svelte:44`), and `▾`/`▸` in `BlockGroup` → chevron SVG (`BlockGroup.svelte:24`); the `✓` in `SequenceLink` (`SequenceLink.svelte:19`) is **removed with no replacement** (completion reads **visually** from the all-covered `ItemMark` chain and, **for assistive tech**, from the mono `{covered}/{total}` count — the `ItemMark` chain is a `<span aria-hidden="true">` with no text node per D5, so the count is the AT-exposed signal, not the chain; T7). **Carve-out (do NOT remove):** the `LATEST_STATUS_META` glyph tokens `✓ · ~ × ! …` (`studentMiniProjects.ts:44-50`) are the deliberate **non-colour, colourblind status signal** (C14) rendered by `StatusPill`; they stay, and `StatusPill.svelte.test.ts:31` continues to assert them. (Tension noted: `ui/StatusBadge.svelte:18-19` cites the same rule to justify having *no* glyph; only `✓` here is pictographic, retained under C14 — an intentional divergence.) Emoji on deferred surfaces are out of scope. **Every new decorative SVG** (the VideoItem check, the checkbox check, the three reveal marks, the BlockGroup chevron, the ItemMark type marks) follows the repo convention (`ItemIcon.svelte:22`, ref `:2113`): `aria-hidden="true"`, `viewBox="0 0 16 16"`, `stroke="currentColor"` (or `fill="currentColor"` for solid marks), `stroke-width` ≈1.6–1.9, round caps/joins, sized ~11–14px, colour inherited from the parent's status/text token — so a reveal mark's meaning reaches AT via the sibling `.sr-only` text, not the SVG. Exact `points`/`path` geometry is plan-level (copy the reference's, e.g. the check at ref `:1039` `polyline points="3,8.6 6.4,12 13,4.6"` — `:1038` is the enclosing strip `<div>`); the focused tests assert `svg[aria-hidden="true"]` on each.
4. **Mono for every numeral** (`--font-mono`) — item counters, "Question N of M", attempts count, progress ratios, the `S{n}` prefix, the numeric-answer field value. Reference mock-ups that spell a number ("Two attempts left", ref 2134) do not override this — the app renders a digit, so it is mono.
5. **Per-component literals — three permitted forms** (verbatim from the Slice-2 plan, `:23`): (a) a geometry literal **matching a reference line, annotated `/* ref NNNN */`**; (b) where the branch has **no reference counterpart**, a literal with a comment stating that and naming the scale it matches; (c) for **implementation mechanics** (sr-only sizing, focus-ring width), a literal with a comment explaining the mechanism. **Literals are geometry ONLY** — never colours (Constraint 1). (Slice-3 uses all three: `/* ref 2127 */` metrics; the no-ref SequenceLink/MiniProjectLink/BlockGroup/StatusPill row metrics; the sr-only 1px box + 2px focus ring copied from `Login.svelte:137-146`.)
6. **Dense control metrics are final** (visual-spec §4): `--control-h` 30px, `--control-pad-x` 9px, field value 13px, `--btn-pad` 4px 10px, `--btn-pad-sm` 4px 9px, code/textarea blocks 8px/10px.

### Decisions (locked in brainstorming; D4 corrected in round 2)

- **D1 — Quiz stays all-at-once (restyle only).** Questions stacked with one Submit; no state/backend change.
- **D2 — Quiz reveal: status-colour + a non-colour mark + screen-reader text, an explicit extension of visual-spec §3** (which assigns green/red to *submission* states, not quiz correctness — `mathion-visual-spec.md:110-122`). *Choice* questions (correct_option_ids present) get a **four-class** reveal (§3), designed so the correct option is **always identified — never hidden**: `reveal-correct` (solid green + check) for a correct option the student **chose OR left unanswered**, `reveal-missed` (dashed green + check) for a correct option not picked **when the student answered**, `reveal-wrong` (red + ×) for a chosen incorrect option, and `reveal-neutral` for the remaining **incorrect, unchosen** options. The three evaluative classes each carry a status colour, a non-colour SVG mark, **and** a visually-hidden status label for assistive tech (the native inputs are `disabled` after reveal, so the colour/mark alone is not exposed to AT); `reveal-neutral` carries no mark/label but **does** carry a recede rule (`--surface-2`/`--muted`/`--border-faint`) so a disabled non-answer row does not read as an interactive pre-submit row (round-9 fix — see §3). *Numeric/Text* questions have **no per-question `is_correct`** (`QuestionReveal`, `types.ts:161-170`), so they show **only the correct answer** and **deliberately do not judge** the student's value.
- **D3 — CourseView adopts an accordion + chain** via a new presentational `ItemMark` primitive (D5). Blocks = §4 accordion sections; each sequence row shows a **non-interactive** `ItemMark` chain + mono progress. The accordion becomes **keyboard-operable** (native `<button>`; enumerated C1).
- **D4 — Footer primary: a three-way predicate.** `flatItems` is **course-wide** and `next()` advances across sequence and block boundaries (`SequencePlayer.svelte:99-100,123-125`); `flatIndex` is `-1` while the item is unresolved (`:112-114`, first render pass before the hash `$effect` `:76-85` runs). The primary Button is:
  - `flatIndex < 0` (unresolved) → **disabled**, label `Next →` (matches today's `disabled` at `:184`);
  - `0 <= flatIndex < flatItems.length - 1` → **enabled** `Next: {next item title} →` (title from the extended `FlatRef`; `Next →` when the title is empty/whitespace), crossing sequence/block boundaries **exactly as today**;
  - `flatIndex === flatItems.length - 1` (course-flat end, today a disabled no-op) → **enabled** `Finish sequence` → `navigate('/courses/{courseSlug}')`.
  Previous = secondary, `disabled={flatIndex <= 0}`, still crossing backward. Disabled buttons carry a **state-appropriate** `title` reason (visual-spec:159): Previous → `title={flatIndex < 0 ? 'Loading…' : flatIndex === 0 ? "You're on the first item" : undefined}` (Previous is disabled for BOTH `-1` and `0`, so a fixed "first item" string is false while unresolved); disabled primary → `title="Loading…"`. **All forward cross-sequence navigation is preserved** — the only change is turning the currently-disabled *terminal* button into an enabled "finish". This adapts ref 10h's `Finish sequence` label (`:1049`, shown there on a sequence's terminal item) to this app's **course-wide** flat model: it appears only at the course-flat end and navigates to `/courses/{slug}`, while sequence-internal boundaries keep `Next: {title} →` (ref 2c). The label is retained despite the sequence-vs-course-flat difference (a deliberate, documented deviation).
- **D5 — New additive primitive `ItemMark.svelte`.** Presentational 22px square + type SVG mark + state, a non-interactive `<span aria-hidden="true">` with **no text node**. Props: `type: Item['type']` (inline indexed type — **no `ItemMarkType` alias**, to keep the public API deterministic), `state: ItemMarkState` with a **`state = 'not-yet'` default** (so consumers with no state — the MiniProjectLink flag — need not supply one); T6 adds exactly `export type ItemMarkState = 'covered' | 'current' | 'not-yet'` to `types.ts`, and `ItemIcon.svelte`'s local `type State` (`:4`) is replaced by importing that shared alias. `ItemIcon.svelte` is **refactored to `<button class="icon {istate}" …><ItemMark type={item.type} state={istate}/></button>`** — the state class **stays on the button** (`ItemIcon.svelte.test.ts:33-36`), the button forwards `state`, gets **`display:inline-flex`** (the rest of a button reset — `padding:0;border:0;background:none;cursor:pointer` — is already global, `reset.css:8`) **and `border-radius: var(--radius)`** (so the global `:focus-visible` ring, `base.css:21-25`, stays rounded once the square/border/state box moves onto `ItemMark` — without it the focus ring on the now-bare button would be square-cornered, `ItemIcon.svelte:54-58`), and keeps `ItemMark`'s SVG reachable as `button svg` (`ItemIcon.svelte.test.ts:28,:39-48`) with empty `textContent` (`:30`). `ItemMark` takes only `type`/`state` (no `class`/other props); consumers that need a class wrap it in a styled span. `SequenceLink` (chain) and `MiniProjectLink` (single flag) use `ItemMark` directly.
- **D6 — `StatusPill` authored from scratch, component-scoped, always rendering `.pill-token`.** It has **no `<style>` block** today; the `pill-*` classes resolve to nothing. T8b writes the pill geometry + class→token table (§4) as **Svelte-component-scoped** CSS, and the component **always renders a `.pill-token` child** (from `LATEST_STATUS_META`). Consequences: (a) the scoped styles travel with `<StatusPill>` to every consumer, including the deferred `MiniProjectDetailPage:425` usage; (b) the **raw** `<span class="pill pill-warning">Late</span>` at `MiniProjectDetailPage:527` and the **separate** teacher-side pill family (`RunMiniProjectsTab:242` with its own scoped `.pill`/`.pill-published`/`.pill-locked` at `:397-412`) are **not reached** by StatusPill's scoped CSS and are each their own surface's responsibility (Slice-4+); (c) scoping (not a global `.pill`) preserves visual-spec §3's one-amber rule.

## Enumerated changes (the non-pure-CSS touches)

All client-side; none touch the backend/routes/schema.

**(A) Behaviour / state:**
1. **`FlatRef` gains `title: string`** (`SequencePlayer.svelte:101-110`) for the footer label. Ordering logic unchanged.
2. **Footer "Finish sequence"** (D4): at the course-flat end only, the primary calls `finish()` → `navigate('/courses/{courseSlug}')`. Existing route (`frontend/src/routes.ts:7`); forward cross-sequence `Next` preserved.
3. **Attempts remaining stays accurate across "Try again"** (`QuizItem`): `attemptsUsed` (`:29-34`) falls back to the course-store count, which `submit()` never bumps and `tryAgain()` (`:96-101`) resets `lastResult` — so after submit→Try again it would read the *stale* store count. **The memo is item-scoped, keyed off the RESPONSE not the reactive prop** (NOT a bare never-reset counter): add `let lastAttempt = $state<{ id: number; count: number } | null>(null)`; set it to **`{ id: res.item_id, count: res.attempt_count }`** on submit success — **`res.item_id` (`QuizSubmitResponse`, `types.ts:152`), NOT `item.id`**, because `item` is a reactive prop read *after* the `await` (`QuizItem.svelte:84` posts, `:85` is `const res = await inflight`, `:87` reads `item.id`), so if the student navigates A→B while A's submit is in flight, `item.id` is already B's and would tag A's count under B (codex round-8 I1, a TOCTOU on the await boundary). The same continuation's existing `markItemCovered(item.id)` (`:87`, not `:88` which is the `} catch`) should likewise use `res.item_id` — it shares the exact latent bug and `res.item_id` is the item the response is *for*. Insert `lastAttempt?.id === item.id ? lastAttempt.count : undefined` into the `attemptsUsed` fallback chain **before** the store lookup; **`tryAgain()` does not reset it** (so within the same item the count survives Try again), but the `id` guard makes it ignored on any other item. **Why item-scoped:** `ItemRouter.svelte:18-19` renders `<QuizItem {item}/>` in a plain `{#if}` and `SequencePlayer.svelte:178` renders `<ItemRouter>` with no `{#key}` (`:177` is the `{#if currentItem && currentCourse.value}` guard), so **quiz→quiz navigation reuses the same `QuizItem` instance** (only the `item` prop swaps) — a bare `lastAttemptCount` would leak item A's count into item B (e.g. submit A → Try again → open B → "2 attempts left" instead of 3). The `id` guard closes exactly that path. (The `lastResult?`/`revealed?` links in the chain are unreachable at the `!locked` render site — kept for correctness.) Client-only. **Out of scope / documented:** the same instance-reuse means `answers`/`lastResult`/`revealed`/`autoRevealed` — and in-flight `submit()` late continuations (`markItemCovered`, the `lastResult` write) — **already** leak across quiz→quiz navigation today; a pre-existing behavioural bug, NOT introduced by Slice-3 (the `res.item_id` keying above bounds the memo + coverage write; the rest is left for the follow-up). Slice-3 does **not** fix it (and `ItemRouter` stays verify-only): the natural fix — `{#key currentItem.id}` on `<ItemRouter>` (or the quiz branch) — would **re-mount every item subtree on every navigation**, re-firing all coverage effects (PageItem's 30 s timer `:11-30`, Video/Interactive on-load coverage), a broad lifecycle change out of place in a restyle slice. Filed as a follow-up; the item-scoped memo above keeps enumerated-3's own "stays accurate" claim true without taking on that change. **Also documented (not a regression, revB-r14-M5):** on a full **remount** — submit → navigate to a *non-quiz* item (unmounts `QuizItem`) → return — `lastAttempt` resets to `null`, so the attempts line reads the store count, which `submit()` never bumps (`SequencePlayer.svelte:16-29` refetches only when `slug !== courseSlug`); it can show a stale "3 attempts left" when 2 remain. This is **identical to today's `(X used)` staleness** (the store count is the same source), NOT introduced by Slice-3 — enumerated 3's memo is scoped to "accurate across Try again" (the reused-instance path), and the remount-staleness is left for the same coverage-store follow-up.
4. **Choice reveal derivations** (§3), **every predicate guarded by `isRevealed = correctOptionIds !== null` so none fires pre-submit** (mirror the existing `{@const}` form — `SingleChoiceQuestion.svelte:19-20` / `MultiChoiceQuestion.svelte:25-26` each read `correctOptionIds !== null && …`; the section header prose "when `correctOptionIds !== null`" does NOT enforce it, the expression must): `isChosen` (`selected === opt.id` for single; **`selected.has(opt.id)`** for multi — `value` is `number[] | string | undefined`, so `.includes` on it would not type-check); `isCorrect = isRevealed && correctSet.has(opt.id)`; **`isWrongPick = isRevealed && isChosen && !isCorrect`**; **`isRevealNeutral = isRevealed && !isCorrect && !isChosen`**. **The `isRevealed &&` on the last two is load-bearing** — they only negate `isCorrect` (false for every option pre-submit), so without the guard a chosen option would turn `reveal-wrong` (red + ×) and the rest `reveal-neutral` (grey recede) **the instant the student picks, before submit** — a regression against today, which renders no `reveal-*` class until reveal (revB-r10-I1). With `studentAnswered` = the student made ≥1 pick (**`SingleChoiceQuestion` `selected !== null` `:12`; `MultiChoiceQuestion` `selected.size > 0`** — `selected` is the derivation site; `valueFor`/`value` is only its source), the **correct option is ALWAYS identified** — `studentAnswered` gates only the *dashed "you missed this" wording*, never *whether* the correct answer shows: `isRevealCorrect = isCorrect && (isChosen || !studentAnswered)` (solid green + "Correct answer", chosen or unanswered) and `isMissedCorrect = isCorrect && !isChosen && studentAnswered` (dashed green + "you missed this"). So the auto-reveal-with-null-`student_answer` case (`studentAnswered === false`) renders a correct option **`reveal-correct` (solid green + check, SR "Correct answer")**, NOT `reveal-neutral` — the correct answer is never hidden, closing the round-9 regression (revB-r9-I2) where the earlier `studentAnswered`-guarded `reveal-neutral` would have shown the correct answer nowhere on the one screen whose purpose is to show it (reachable: auto-reveal at `attempt_count >= max`, `QuizItem.svelte:49-63`, with the backend filling `student_answer=None` for any question absent from the stored map, `backend/mathion/api/quiz.py:201`). `reveal-neutral` is now reserved for **incorrect, unchosen** options only.

(Ratio conventions are intentionally context-specific: the SequenceLink **progress** ratio is `{covered}/{total}` no-spaces, matching CourseCard; the quiz **score** stays `{correct} / {total}` with spaces, `QuizItem.svelte:164` — a score, not a progress count.)
