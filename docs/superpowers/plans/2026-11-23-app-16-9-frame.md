# Student App Frame 16:9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The student app frame becomes 16:9 (like the editor preview) and, under 800 px of width, is replaced by a "larger screen" note that loads nothing and covers nothing.

**Architecture:** `InteractiveAppItem` measures its article with a ResizeObserver (`{@attach}`); a `wide` derived gates the existing fetch-and-cover effect. The `.app-card` gets the editor preview's 16:9 width rule; `InteractiveFrame` always fills its parent (600 px default and `fill` prop removed). A new author page `docs/interactive-apps.md` states the app rules.

**Tech Stack:** Svelte 5 runes, TypeScript, Vitest + jsdom (mount/unmount/flushSync), zsh gate script.

**Spec:** `docs/superpowers/specs/2026-11-23-app-16-9-frame-design.md` (approved 2026-11-23)

## Global Constraints

- Minimum app size 800 × 450; `MIN_APP_WIDTH = 800` (CSS px of the page, after any `--app-zoom`).
- Note copy, exact: `This app needs a larger screen. Open this page on a laptop or desktop computer.`
- Under 800 px: no source fetch, no coverage tracker, no cover hint. Coverage already credited stays.
- Until the width is known: nothing loads, nothing shows below the title.
- Window height in the size rule is divided by `var(--app-zoom, 1)`, as in `AppBody.svelte:337`.
- No new dependencies; Svelte 5 only; code comments one short line; no `fill` prop left anywhere.

## Review Focus

1. Width jitter around 800 while the source fetch is in flight: the stale fetch must not render or cover (test 7 below).
2. Narrow → wide → narrow → wide: exactly one `/track` per item overall (test 5).
3. A 1280 × 720 window: title, the app and the pinned bottom bar fit without scrolling where the rule allows; at 1512 × 860 the app is 928 × 522 (browser check, step 8).
4. The editor preview after `fill` is removed: still 16:9 at the same size (browser check, step 8).
5. `script_url` null on a narrow screen: "No app uploaded yet." wins over the note (test 6).

- [ ] **Step 3: Implement**

- `InteractiveAppItem.svelte`: `let width = $state<number | null>(null)`; `{@attach}` on the article creates a `ResizeObserver` writing `entries[0].contentRect.width` to `width` and disconnects on teardown; `const wide = $derived(width !== null && width >= MIN_APP_WIDTH)`. The effect reads `wide` after the `!filename` branch: not wide → `status = width === null ? 'loading' : 'narrow'`, `source = null`, return (so the teardown aborts an in-flight fetch). `status` gains `'narrow'`. Template: `'narrow'` renders `<div class="app-card narrow"><p class="notice">{NOTE}</p></div>`; `'loading'` renders nothing below the title, as today. Ruling over the spec's `bind:clientWidth` example: an explicit observer so jsdom tests can drive it.
- `.app-card`: `aspect-ratio: 16 / 9; width: min(100%, max(800px, (calc(100vh / var(--app-zoom, 1)) - <R>px) * 16 / 9)); margin-inline: auto;` where `<R>` is the student page's chrome reserve measured in step 8 (start at 300). The narrow card drops the ratio (`.app-card.narrow { aspect-ratio: auto; width: auto; padding: var(--space-3); }`).
- `InteractiveFrame.svelte`: remove `fill`; `.frame { width: 100%; height: 100%; }` (no margin); header comment says the frame takes its parent's size. Drop the now-pointless `.app-card :global(.frame) { margin-bottom: 0; }` and its comment.
- `AppBody.svelte:273`: drop the `fill` attribute.
